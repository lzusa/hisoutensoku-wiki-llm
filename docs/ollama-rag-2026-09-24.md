# Ollama 接入 Wiki 检索复测（2026-09-24）

## 配置

- 本地模型：`soku-wiki-pilot`，Qwen3-4B-Instruct-2507 加小样本 LoRA 后量化为 Q4_K_M GGUF。
- 语料：从上游 Wiki commit `b03bd40710774725f8053780c547514d83fd226e` 构建的 428 个片段。
- 检索：`scripts/retrieve.py` 词法排序，取前 3 个片段；`scripts/ask_ollama.py` 调用 Ollama `/api/chat`，温度 0。
- 为兼容 `60F` 与 Wiki 里的 `60` 写法，检索时额外索引字母数字混合词的数字和字母部分。
- 测试：与首次试验相同的 8 道未见过的 FAQ 页面问答，结果仅存本地 `outputs/ollama-rag-test.jsonl`。

## 结果

| 方式 | 8 题关键事实 | 对应页面在前 3 个检索结果中 |
| --- | ---: | ---: |
| 裸模型，首次试验 | 0/8 | 不适用 |
| Ollama 模型 + Wiki 检索，本次 | 8/8 | 8/8 |

人工逐题对照参考答案，8 条回答都包含所问的关键事实。部分回答省略了参考答案里的操作细节，因此这个数字不表示回答完全一致，也不表示所有资料都已覆盖。将“练习模式右下角显示 60F 而不是正常的多少帧？”改写为“练习模式显示 60F，正常应该是多少？”后，检索前 3 个结果仍包含正确页面，Ollama 回答 62F。另以 `--top-k 0` 模拟无资料输入，模型答复未找到答案；这尚不能证明自然检索无关资料时不会猜测。检索资料 URL 由程序列出，不把模型生成的出处当作证据。

这个结果支持先用检索提供 Wiki 知识。此前 LoRA 只用 20 条问答、3 个优化步骤训练，单纯增加训练轮数无法替代更多高质量数据；在扩充并核对训练与测试集之前，不把当前 GGUF 当作可靠的独立 Wiki 问答模型。
